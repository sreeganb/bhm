\section*{Detailed Mathematical Explanation of the PairSampler Code}

This document explains the core mathematical ideas behind the \texttt{PairSampler} class. The class seeks to place particles of various types in a three-dimensional box in such a way that (1) certain minimum distances are respected (exclusion), and (2) observed or desired inter-particle distances are matched by minimizing the negative log-likelihood of a Gaussian-based distance model.

\subsection*{1. Initialization of Positions}

The code generates initial positions for each type of particle:
\[
\text{positions}[t] \sim \mathcal{U}(0,\text{box\_size})^{N \times 3},
\]
where $t$ is the particle type (\emph{e.g.,} "A", "B", "C"), and $N$ is the number of particles of type $t$. This creates a random arrangement in a cubic volume of size $\texttt{box\_size}$. 

\subsection*{2. Gaussian Negative Log-Likelihood for Pairwise Distances}

To measure how well any two particles match a desired \emph{target distance}, the code computes a \textit{negative log-likelihood}. If we have two sets of coordinates,
\[
\mathbf{r}_1, \mathbf{r}_2 \in \mathbb{R}^{3},
\]
the Euclidean distance $d(\mathbf{r}_1, \mathbf{r}_2)$ is
\[
d(\mathbf{r}_1, \mathbf{r}_2) = \sqrt{(\mathbf{r}_1 - \mathbf{r}_2)^\top(\mathbf{r}_1 - \mathbf{r}_2)}.
\]
The code uses a Gaussian model for the likelihood that the distance is near a \emph{target} distance $\mu$ with a tolerance $\sigma$:
\[
\text{likelihood}(d) = \exp\!\Bigl(-\frac{(d - \mu)^2}{2 \sigma^2}\Bigr).
\]
To prevent numerical underflow, the code clips the likelihood at a minimum value $\epsilon$ (here, $10^{-10}$). Then, the negative log-likelihood for a single pair is
\[
-\log \max\Bigl(\exp\!\bigl(-\frac{(d - \mu)^2}{2 \sigma^2}\bigr), \, \epsilon\Bigr).
\]
For multiple particles in sets $\{\mathbf{r}_{1,i}\}_{i=1}^m$ and $\{\mathbf{r}_{2,j}\}_{j=1}^n$, the code constructs a matrix of negative log-likelihoods:
\[
\bigl[M(i,j)\bigr]_{m \times n} 
= -\log \max\Bigl(\exp\!\bigl(-\frac{(d(\mathbf{r}_{1,i}, \mathbf{r}_{2,j}) - \mu)^2}{2 \sigma^2}\bigr), \, \epsilon\Bigr).
\]
It then performs a procedure to select minimal entries (representing the best pairs) and sums them up.

\subsection*{Best Pair Selection Procedure}

After constructing the negative log-likelihood matrix 
\[
M(i,j), 
\]
the code proceeds to identify ``best pairs'' by selecting the minimum entry in each row and each column. In more formal mathematical terms, suppose \(M\) is an \(m \times n\) matrix where \(M(i,j)\) is the negative log-likelihood for pairing particle \(i\) (among the \(m\) particles of a certain type) with particle \(j\) (among the \(n\) particles of another type). We perform the following steps:

\begin{enumerate}
    \item \textbf{Row-minima selection:} For each row \(i \in \{1,2,\ldots,m\}\), find 
    \[
    r_i = \arg\min_{j \in \{1,\ldots,n\}} \; M(i,j).
    \]
    We then select the pair \((i, r_i)\).

    \item \textbf{Column-minima selection:} For each column \(j \in \{1,2,\ldots,n\}\), find 
    \[
    c_j = \arg\min_{i \in \{1,\ldots,m\}} \; M(i,j).
    \]
    We then select the pair \((c_j, j)\).

    \item \textbf{Combine unique pairs:} Let 
    \[
    U = \left\{(i, r_i)\,\big\vert\, i = 1,\ldots,m\right\} \;\cup\; 
         \left\{(c_j, j)\,\big\vert\, j = 1,\ldots,n\right\}.
    \]
    In other words, \(U\) is the union of all row-wise minima and column-wise minima.

    \item \textbf{Sum the matrix entries:} The code sums up \(M(i,j)\) over all unique pairs in \(U\):
    \[
    \text{Sum} = \sum_{(i,j) \in U} M(i,j).
    \]
\end{enumerate}

This procedure ensures that for every row, at least one minimal element is included, and for every column, at least one minimal element is included. In practical terms, it captures pairs that best satisfy the distance-based likelihood constraints from both the row (\(\arg\min\)) and the column (\(\arg\min\)) perspectives, ensuring that no row or column's minimal pairing is overlooked.

Note that this method is not a full \emph{global} matching (like the Hungarian algorithm would be). Instead, it is a simpler heuristic that collects the best row-wise and column-wise partners, then sums their negative log-likelihood values. As a result, it effectively retains those interactions that contribute the smallest penalty (or highest likelihood) for each row and each column:

\[
\text{NLL total contribution} \;=\;
\sum_{(i, j) \in U} M(i,j).
\]

Collecting these minimal pairs in the set \(U\) and summing their negative log-likelihood matrix entries provides a focused measure of how close each particle can come to its ``best'' partner, either from the row or column perspective.

\subsection*{3. Exclusion Energy (Excluded Volume Term)}

To avoid overlapping of particles, each pair of particles has a minimum distance:
\[
d_{\mathrm{min}} = R_1 + R_2,
\]
where $R_1$ and $R_2$ are the radii of the corresponding particle types. If a particle pair is closer than $d_{\mathrm{min}}$, the code exacts a penalty proportional to
\[
\bigl(d_{\mathrm{min}} - d(\mathbf{r}_1,\mathbf{r}_2)\bigr)^2,
\]
scaled by a large constant $k_{\mathrm{exclude}}$. Summing this penalty for each violating pair yields:
\[
\mathrm{NLL}_{\mathrm{excl}} = k_{\mathrm{exclude}} \sum_{\substack{i,j\,:\,\\ d(\mathbf{r}_{i}, \mathbf{r}_{j}) < d_{\mathrm{min}}}} 
\Bigl[d_{\mathrm{min}} - d(\mathbf{r}_{i}, \mathbf{r}_{j})\Bigr]^2.
\]

\subsection*{4. Total Negative Log-Likelihood}

The code combines both terms: the sum of negative log-likelihood for \emph{matching} desired inter-particle distances, plus the exclusion penalty. We can write it as:
\[
\mathrm{NLL}_{\mathrm{total}}(\{\mathbf{r}\}) 
= \mathrm{NLL}_{\mathrm{excl}}(\{\mathbf{r}\}) 
+ \sum_{\substack{\text{types }(t_1, t_2)}} 
\sum_{\substack{i,j}}\! M_{t_1,t_2}(i,j),
\]
where $M_{t_1,t_2}(i,j)$ denotes the negative log-likelihood matrix entry for the distance between particle $i$ of type $t_1$ and particle $j$ of type $t_2$, considering the minimal combination over each row and column to avoid double counting.

\subsection*{5. Summary}

In essence, the code:

\begin{enumerate}
\item Randomly initializes particle positions in a 3D box. 
\item Uses a Gaussian-based negative log-likelihood term to encourage particle distances to match certain target distances within a given tolerance.
\item Penalizes particles that overlap (excluded volume term).
\item Sums these contributions to get a total negative log-likelihood, \(\mathrm{NLL}_{\mathrm{total}}\), which the code can then attempt to minimize.
\end{enumerate}

This approach enables stochastic sampling or energy minimization to place particles according to the desired distances between pairs and to prevent them from occupying the same space.

\section*{Mathematical Explanation of the \texttt{TetramerSampler} Code}

\textbf{Context:} This class extends a \texttt{PairSampler} to include special ``tetramer moves'' in a Monte Carlo (MC) framework. A tetramer here is defined as a set of four particles of types A, B, C, C (i.e., one A, one B, and two Cs). The code seeks to place them close to certain target distances through a Markov Chain Monte Carlo (MCMC) procedure.

\subsection*{1. Monte Carlo Loop in \texttt{run\_mc}}

\begin{enumerate}
    \item \textbf{Initialization:} 
    \[
      \text{positions} \gets \text{initialize\_positions()}
    \]
    with an initial score 
    \[
      E_{\text{current}} = \text{calculate\_score}(\text{positions}).
    \]
    Also, we keep track of:
    \[
      E_{\text{best}} = E_{\text{current}}, \quad \text{positions}_{\text{best}} = \text{positions}.
    \]
    \item \textbf{Temperature Schedule:} A cooling schedule modifies the temperature \(T\) at each iteration \(\text{step}\). Given an initial temperature \(T_{\text{init}}\) and a final temperature \(T_{\text{final}}\), the temperature at step \(\text{step}\) (out of \(n_{\text{steps}}\) total) is set to
    \[
      T(\text{step}) = T_{\text{init}} \left(\frac{T_{\text{final}}}{T_{\text{init}}}\right)^{\frac{\text{step}}{n_{\text{steps}}}}.
    \]
    \item \textbf{Move Types:} With probabilities 0.4, 0.1, and 0.5 respectively, the code chooses one of:
    \[
      \begin{cases}
      \text{``position'' move},\\
      \text{``sigma'' move},\\
      \text{``tetramer'' move}.
      \end{cases}
    \]
    Depending on the choice, a proposed state \((\text{proposed\_positions}, \text{proposed\_sigma})\) is generated.

    \item \textbf{Energy Calculation and Metropolis Acceptance:} 
    The proposed state's score \(E_{\text{proposed}} = \text{calculate\_score}(\text{proposed\_positions})\). The energy difference is
    \[
      \Delta E = E_{\text{proposed}} - E_{\text{current}}.
    \]
    We accept the move if 
    \[
      \Delta E < 0 \quad \text{or} \quad \exp\!\bigl(-\Delta E / T\bigr) > \mathcal{U}(0,1),
    \]
    where \(\mathcal{U}(0,1)\) is a uniform random draw between 0 and 1. If accepted, we set
    \[
      \text{positions} \gets \text{proposed\_positions}, \quad E_{\text{current}} \gets E_{\text{proposed}}.
    \]
    If the new score is better than the best score so far, we record it as 
    \[
      E_{\text{best}} \gets E_{\text{proposed}}, \quad \text{positions}_{\text{best}} \gets \text{proposed\_positions}.
    \]

    \item \textbf{Trajectory Storage:} Every \(\text{save\_freq}\) steps, the code stores current state information (positions, energy, etc.) and prints a log message.

\end{enumerate}

\subsection*{2. Identifying Tetramers: \texttt{get\_tetramers}}

A \textit{tetramer} in this code is an (A, B, C, C) tuple identified by minimum distances:
\[
\text{For each } i \text{ in positions['A']}, \quad 
   \text{choose } b = \arg\min_j \bigl\|\mathbf{r}_{A,i} - \mathbf{r}_{B,j}\bigr\|.
\]
Then find two \texttt{C} indices \(c_1\) and \(c_2\) such that 
\[
(c_1,c_2) = \arg\min_{k,l} \Bigl(\bigl\|\mathbf{r}_{B,b} - \mathbf{r}_{C,k}\bigr\| + \bigl\|\mathbf{r}_{B,b} - \mathbf{r}_{C,l}\bigr\|\Bigr),
\]
or equivalently, it sorts all \(\bigl\|\mathbf{r}_{B,b} - \mathbf{r}_{C,k}\bigr\|\) in ascending order and picks the first two elements. Each tetramer is thus stored as \((i,b,c_1,c_2)\).

\subsection*{3. Scoring a Tetramer: \texttt{calculate\_tetramer\_score}}

For a given tetramer, composed of indices \((i,b,c_1,c_2)\), the code calculates the sum of pairwise negative log-likelihood scores:
\[
\text{score}_{AB} = \text{calculate\_pair\_score}\bigl(\mathbf{r}_{A,i}, \mathbf{r}_{B,b},\, \mu_{AB},\, \sigma_{AB}\bigr),
\]
\[
\text{score}_{BC1} = \text{calculate\_pair\_score}\bigl(\mathbf{r}_{B,b}, \mathbf{r}_{C,c_1},\, \mu_{BC},\, \sigma_{BC}\bigr),
\quad
\text{score}_{BC2} = \text{calculate\_pair\_score}\bigl(\mathbf{r}_{B,b}, \mathbf{r}_{C,c_2},\, \mu_{BC},\, \sigma_{BC}\bigr),
\]
\[
\text{score}_{C1C2} = \text{calculate\_pair\_score}\bigl(\mathbf{r}_{C,c_1}, \mathbf{r}_{C,c_2},\, \mu_{CC},\, \sigma_{CC}\bigr).
\]
The total tetramer score is 
\[
\text{score}_{\text{tetramer}} = \text{score}_{AB} + \text{score}_{BC1} + \text{score}_{BC2} + \text{score}_{C1C2}.
\]

\subsection*{4. Overall System Score: \texttt{calculate\_score}}

This function adds:
\[
\text{score}_{\text{pairs}}(\mathbf{r}) + \sum_{\substack{\text{tetramer } T}} \text{score}_{\text{tetramer}}(T),
\]
where \(\mathbf{r}\) is the current set of positions, and \(\text{score}_{\text{pairs}}(\mathbf{r})\) is inherited from \texttt{PairSampler} (covering all pairwise distance constraints among A, B, C). Then each identified tetramer $T$ contributes additional constraints through \(\text{calculate\_tetramer\_score}\).

\subsection*{5. Proposing a Tetramer Move: \texttt{propose\_tetramer\_move}}

\begin{enumerate}
    \item \textbf{Identify a Random Tetramer:}
    \[
      i = \text{random index in A}, \quad
      b = \arg\min_j \bigl\|\mathbf{r}_{A,i} - \mathbf{r}_{B,j}\bigr\|,
    \]
    \[
      c_1, c_2 = \arg\!\min_{k,l}\bigl\|\mathbf{r}_{B,b} - \mathbf{r}_{C,k}\bigr\|, \quad \text{picking the two closest C's}.
    \]
    \item \textbf{Random Displacement:} A Gaussian displacement \(\Delta \mathbf{r}\) is sampled from \(\mathcal{N}(\mathbf{0}, \sigma^2 I)\), here $\sigma=5$ in each dimension. This displacement is then added to all four particles $(A_i, B_b, C_{c_1}, C_{c_2})$:
    \[
      \mathbf{r}'_{A,i} \gets \mathbf{r}_{A,i} + \Delta \mathbf{r}, \quad
      \mathbf{r}'_{B,b} \gets \mathbf{r}_{B,b} + \Delta \mathbf{r}, \quad
      \mathbf{r}'_{C,c_1} \gets \mathbf{r}_{C,c_1} + \Delta \mathbf{r}, \quad
      \mathbf{r}'_{C,c_2} \gets \mathbf{r}_{C,c_2} + \Delta \mathbf{r}.
    \]
    Thus, the entire tetramer is effectively translated by a random vector.
    \item \textbf{Return Proposed State:} The updated positions are a copy of the old state with only the chosen tetramer's coordinates changed.
\end{enumerate}

\section*{Summary}

By combining a \textbf{tetramer-aware} scoring mechanism and a specialized \textbf{tetramer proposal move}, this approach fosters closer adherence to the intended distances among groups of four particles (A-B-C-C). The MCMC loop, with an annealing-style temperature schedule, guides the system toward configurations that minimize the overall energy (negative log-likelihood) while exploring potential global minima.

def calculate_exclusion_score(self, positions: Dict[str, np.ndarray]) -> float:
    """Calculate score term for excluded volume"""
    score = 0.0

def calculate_pair_score(self, pos1: np.ndarray, pos2: np.ndarray, 
                         target_dist: float, sigma: float) -> float:

def propose_sigma_move(self) -> Dict[str, float]:
    """Propose new sigma values"""
    new_sigma = self.sigma.copy()
    # Pick random pair type
    pair_type = np.random.choice(list(self.sigma.keys()))
    
    # Propose new value in log space
    log_sigma = np.log(new_sigma[pair_type])
    step_size = 0.1
    new_log_sigma = log_sigma + np.random.normal(0, step_size)

    new_log_sigma = np.clip(new_log_sigma, np.log(0.5), np.log(20.0))
    new_sigma[pair_type] = np.exp(new_log_sigma)

\subsubsection{\texttt{run\_mc}}
\begin{lstlisting}[language=Python]
def run_mc(self, n_steps: int = 50000, save_freq: int = 100) -> Tuple:
    """Base Monte Carlo sampling with position and sigma moves"""
    positions = self.initialize_positions()
    current_score = self.calculate_score(positions)
    
    best_positions = {k: v.copy() for k, v in positions.items()}
    best_score = current_score
    
    self.trajectory = []
    accepted = 0
    
    # Temperature schedule
    initial_temp = 10.0
    final_temp = 0.1
    
    for step in range(n_steps):
        temp = initial_temp * \
               (final_temp / initial_temp)**(step / n_steps)
        
        # 90% chance position move, 10% sigma move
        if np.random.random() < 0.9:
            proposed_positions = self.propose_position_move(positions)
            proposed_sigma = self.sigma.copy()
        else:
            proposed_positions = positions.copy()
            proposed_sigma = self.propose_sigma_move()
        
        # Store old sigma, set new sigma
        old_sigma = self.sigma.copy()
        self.sigma = proposed_sigma
        
        # Calculate new score
        proposed_score = self.calculate_score(proposed_positions)
        delta_e = proposed_score - current_score
        
        # Metropolis criterion
        if delta_e < 0 or np.random.random() < np.exp(-delta_e/temp):
            positions = proposed_positions
            current_score = proposed_score
            accepted += 1
            
            if current_score < best_score:
                best_score = current_score
                best_positions = {k: v.copy() for k, v in positions.items()}
        else:
            self.sigma = old_sigma
        
        # Save trajectory info periodically
        if step % save_freq == 0:
            self.trajectory.append(self.save_state(step, positions, current_score))
            print(f"Step {step}, Score: {current_score:.2f}, "
                  f"T: {temp:.4f}, Accept: {accepted/(step+1):.2f}")
    
    return best_positions, self.trajectory, self.save_trajectory()
\end{lstlisting}

\begin{itemize}
    \item \textbf{Initialization:} Positions are set randomly, and a score is calculated.
    \item \textbf{Temperature Schedule:} A linear, geometric, or exponential cooling schedule can be used. Here, the code transitions from \texttt{initial\_temp}=10.0 to \texttt{final\_temp}=0.1 over \texttt{n\_steps}.
    \item \textbf{Move Selection:}
        \begin{itemize}
            \item With 90\% probability, perturb the \texttt{positions}.
            \item Otherwise, propose a new $\sigma$ for one pair type.
        \end{itemize}
    \item \textbf{Metropolis Criterion:} 
    \[
        \Delta E = \texttt{proposed\_score} - \texttt{current\_score}
        \quad \text{and} \quad
        p_{\text{accept}} = \exp \left(-\frac{\Delta E}{T}\right).
    \]
    If $\Delta E < 0$ (improvement) or if a random number $< p_{\text{accept}}$, the move is accepted.
    \item \textbf{Saving Trajectory:} Every \texttt{save\_freq} steps, the state is stored and a progress message is printed.
    \item \textbf{Return Value:} The function returns the best positions found, the full trajectory, and a call to \texttt{save\_trajectory()} that writes the trajectory to a file.
\end{itemize}
